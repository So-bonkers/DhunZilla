## Context - why this exists
The app's mixer meters, and later the copilot, need "how loud is each track and the master?" without a GUI and
without writing WAV files. This package adds a NEW engine module `op::meters` and an `opd meters` command that
renders the stems and the master mix **in memory** (`op::render_stems`) and measures each buffer with the
EXISTING `op::analyze::analyze_samples` (sample peak dBFS, RMS dBFS, BS.1770 integrated LUFS). It adds **no new
DSP**, never writes a file and never modifies the project: read-only and deterministic.
Nothing existing is modified except two small additive edits (CMake registration, one CLI dispatch block).

Existing APIs this module uses (read their headers, do not change them): `op::render_stems` in
`src/engine/render.hpp`; `op::analyze::analyze_samples` and its result struct in `src/engine/analyze.hpp`;
`wav::StereoBuffer` in `src/engine/wav.hpp`; `op::Project` / `op::load_project` in `src/engine/model.hpp`.

### API (exactly this, namespace `op::meters`, in `src/engine/meters.hpp`)
```cpp
#pragma once
#include <optional>
#include <string>
#include <vector>
#include "engine/model.hpp"
#include "engine/wav.hpp"
namespace op::meters {
struct Meter {
    std::optional<double> peak_dbfs;
    std::optional<double> rms_dbfs;
    std::optional<double> integrated_lufs;
};
struct TrackMeter {
    std::string name;   // Track::name as stored (may be empty)
    Meter meter;
};
struct Report {
    int sample_rate = 0;
    long long frames = 0;          // frames of the full render (identical for every stem and the master)
    double duration_s = 0.0;       // frames / sample_rate (0.0 when sample_rate <= 0)
    std::vector<TrackMeter> tracks;  // project track order, one entry per track (index = position)
    Meter master;                    // the full mix (includes master_gain_db)
};
Meter meter_buffer(const wav::StereoBuffer& buf);
bool measure_project(const Project& p, const std::string& base_dir, Report& out, std::string& err);
std::string to_json(const Report& r);
}
```
- `meter_buffer`: if `buf.frames() == 0` return a Meter with all three empty. Otherwise
  `f = op::analyze::analyze_samples(buf.interleaved, 2, buf.sample_rate)` and copy `f.peak_dbfs`, `f.rms_dbfs`,
  `f.integrated_lufs` unchanged (same `std::optional` values, so an all-zero buffer gives three empty optionals).
- `measure_project`: call `op::render_stems(p, base_dir, stems, mix, err)`; on failure return `false` with `err`
  exactly as `render_stems` set it. On success fill `out` (a fresh `Report`): `sample_rate = mix.sample_rate`,
  `frames = mix.frames()`, `duration_s = frames / sample_rate`, `tracks[i] = {p.tracks[i].name,
  meter_buffer(stems[i])}` for every track in order (muted / un-soloed tracks are all-zero stems, so their
  meter is three nulls), `master = meter_buffer(mix)`. The master is the mix as `render_stems` returns it (so
  `master_gain_db` is applied); do not re-sum the stems.
- Nothing is written to disk by any function in this module.

### JSON (`to_json`, byte-exact; text ends with `}\n`)
Example (two tracks; the second is inaudible):
```
{
  "sample_rate": 48000,
  "frames": 192000,
  "duration_s": 4.000000,
  "tracks": [
    {"index": 0, "name": "kick", "peak_dbfs": -6.0206, "rms_dbfs": -12.3456, "integrated_lufs": -14.0000},
    {"index": 1, "name": "pad", "peak_dbfs": null, "rms_dbfs": null, "integrated_lufs": null}
  ],
  "master": {"peak_dbfs": -6.0206, "rms_dbfs": -12.3456, "integrated_lufs": -14.0000}
}
```
- Top-level keys in this order: `sample_rate`, `frames`, `duration_s`, `tracks`, `master`; 2-space indent for those
  keys, 4 spaces before each track object, `\n` line endings, one `\n` after the final `}`.
- Each track object is ONE line: `{"index": <i>, "name": <json string>, "peak_dbfs": <n>, "rms_dbfs": <n>,
  "integrated_lufs": <n>}`; objects separated by `,\n`; `index` is the 0-based track position as a plain integer.
- `master` is the one-line object `{"peak_dbfs": <n>, "rms_dbfs": <n>, "integrated_lufs": <n>}` (no index/name).
- `sample_rate` and `frames` plain integers; `duration_s` printed with `%.6f`; every dBFS/LUFS number with `%.4f`
  (via `snprintf`; the text `-0.0000` is printed `0.0000`); an empty optional prints the bare word `null`.
- JSON string escaping for `name`: wrap in `"`; escape `"` as `\"`, `\` as `\\`, any byte < 0x20 as `\u00XX`
  (4 lowercase hex digits); every other byte (including UTF-8) verbatim.
- With zero tracks the tracks line is exactly `  "tracks": [],` (library only: `opd` projects always have >= 1 track).

### CLI
`opd meters <project.opj>` - exactly one argument that does not start with `-`. Loads the project with
`op::load_project`, then `measure_project(p, <directory of the project file>, r, err)`, prints `to_json(r)` to
stdout and nothing else. No `--seed` or other options exist (an extra/unknown argument is a usage error).
Errors print NOTHING on stdout and use the existing `fail(...)` helper, checked in this order:
1. wrong argument count (no argument, or more than one) or an argument starting with `-` -> `usage()` then
   `fail("usage", "meters needs exactly <project.opj>")` -> exit 2;
2. file does not exist -> `fail("not_found", <path>)` -> exit 3;
3. `load_project` fails -> `fail("parse", err)` -> exit 4;
4. project `sample_rate` outside [8000, 192000] -> `fail("meters", "unsupported sample rate <N>")` -> exit 5;
5. `measure_project` fails -> `fail("render", err)` -> exit 5.

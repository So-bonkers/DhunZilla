## Context - why this exists
The Phase 1 transport (time signature, bar/beat ruler, tempo map, click track) has render goldens for 3/4
(`tests/fixtures/goldens/time_sig_3_4.opj`) and for a mid-song tempo drop (`tests/fixtures/goldens/tempo.opj`),
but never both at once, and **no golden covers `opd click` at all**. A regression that moves an accent off a
bar's first beat in 3/4, or mis-maps clicks across a tempo change, would ship unnoticed. This package adds
harness coverage only: a small transport fixture project built from `opd new` plus an op journal, a bit-exact
golden for its `opd click` render, and a harness script that asserts the accents fall on the first beat of
every bar under 3/4. **Nothing in `src/` changes: no engine, CLI, model, op or spec behaviour is added or
altered.** Existing code this package drives (read it first, do not reimplement or change it): `opd new`,
`opd apply`, `opd click`, `opd timeline` in `src/cli/main.cpp`; `op::render_click` / `op::beat_onsets` in
`src/engine/render.cpp` (spec `docs/spec/project-model.md` §"Click track render — `opd click` (WP-0148)");
the ruler `opd timeline` (WP-0210); the journal ops `set_time_signature` and `set_length_bars`
(`docs/spec/operations.md`).

### The fixture project — the make script's recipe IS this (normative)
Usage `bash harness/make_transport_golden.sh [path/to/opd] [out_dir]`; `out_dir` defaults to
`tests/fixtures/transport`; it writes `transport_3_4_tempo.opj` and `transport_3_4_tempo.click.sha256` into
`out_dir` and nothing else. Steps, in this order, with all intermediates in a `mktemp -d` temp dir:
1. `"$OPD" new "$TMP/base.opj" --bars 2 --bpm 120`
2. `"$OPD" apply "$TMP/base.opj" tests/fixtures/transport/transport_3_4_tempo.opjl -o "$TMP/signed.opj"`
3. stdlib python inserts the tempo map: `proj["tempo_map"] = [{"bar": 0.0, "bpm": 120.0}, {"bar": 2.0, "bpm": 90.0}]`
   then `json.dump(proj, open(path, "w"), sort_keys=True)`. **No operation in `docs/spec/operations.md` can
   express a tempo map**, so this step writes JSON directly: do NOT add an op (`set_tempo_map` would be an
   engine change); write a `PROPOSE:` note in the handoff instead.
4. `"$OPD" apply "$TMP/signed.opj" "$TMP/empty.opjl" -o "$OUT/transport_3_4_tempo.opj"` where
   `$TMP/empty.opjl` is an empty file — `opd apply` re-saves through the canonical writer, so the committed
   `.opj` bytes are canonical and reproducible.
5. `"$OPD" click "$OUT/transport_3_4_tempo.opj" -o "$TMP/click.wav"` then
   `sha256sum "$TMP/click.wav" | cut -d' ' -f1 > "$OUT/transport_3_4_tempo.click.sha256"`.

The committed project must be exactly: `format_version` 0, `sample_rate` 48000, `bpm` 120.0, `seed` 42,
`length_bars` 4.0, `beats_per_bar` 3 (no `time_signature` key: 3/4 normalises to `beats_per_bar`),
`tempo_map` `[{"bar": 0.0, "bpm": 120.0}, {"bar": 2.0, "bpm": 90.0}]`, one `Synth` track, one empty pattern,
one arrangement clip `{pattern: 0, start_bar: 0.0, repeats: 1}`. Therefore `opd timeline` on it prints exactly:
`beats_per_bar` 3, `time_signature` `"3/4"`, 4 bars, `start_beat` `0.0, 3.0, 6.0, 9.0`, `bpm`
`120.00, 120.00, 90.00, 90.00` (the tempo drop is at bar 2, i.e. mid-song), `start_sample`
`0, 72000, 144000, 240000`.

### The click analysis (normative — these exact numbers are the contract)
Read the WAV with stdlib `wave` + `array` (little-endian `int16`); `left = frames[0::2]`.
- **Onset locator:** index `i` with `left[i] == 16384` (a burst starts at `x[0] = 0.5` → PCM16 16384). There
  must be exactly 12 onsets, at
  `[0, 24000, 48000, 72000, 96000, 120000, 144000, 176000, 208000, 240000, 272000, 304000]`
  (12 beats = 4 bars × 3 beats; a beat is 24000 samples at 120 bpm and 32000 samples at 90 bpm, so the
  tempo drop is visible as a spacing change between beats 5 and 6).
- **Accent classifier:** for the window of `BURST = sample_rate * 30 / 1000` = 1440 samples starting at an
  onset, count sign changes between consecutive **non-zero** samples of `left`. A 1500 Hz click gives
  exactly 90, a 1000 Hz click exactly 60. The 12 counts, in onset order, must be exactly
  `[90, 60, 60, 90, 60, 60, 90, 60, 60, 90, 60, 60]`.
- **The accent assertion:** an onset is accented iff its count is >= 75 (75 sits midway between 60 and 90 —
  do not pick a tighter threshold). The accented onsets must be exactly the four bar starts
  `[0, 72000, 144000, 240000]`: every bar's first beat in 3/4, no accent anywhere else, 4 accents in total.
- Silence after the last burst: every sample of `left[304000 + 1440:]` is 0.

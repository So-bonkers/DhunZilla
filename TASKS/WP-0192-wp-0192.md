## Context — why this exists
FL Studio has "pattern mode" (audition one pattern on loop) and "song mode" (play the playlist). DhunZilla only has
song mode: `opd render` always follows the arrangement. This package adds a **read-only** pattern mode to
`opd render`: render one named pattern, `--loops N` times, using the pattern's own `length_beats`, `swing` and
track, ignoring the arrangement. No model change, no new op, no new project key. Without `--pattern` nothing
changes (all goldens stay bit-identical).

## Spec — normative
`docs/spec/project-model.md` already contains a new section "Pattern mode — additive (WP-0192)" (the runner copies
it in before you start, on top of current `main`'s spec — the change is purely additive; keep it that way). It is the contract; do not edit it. Summary (the spec section wins on any difference):

- `opd render <proj.opj> -o <out.wav> --pattern NAME [--loops N] [other render options]`.
  NAME is matched byte-for-byte against `patterns[i].id`; unnamed patterns cannot be selected. N is a decimal
  integer in `[1, 1000]` (digits only), default 1. Repeating `--pattern` or `--loops`: last value wins.
- **Pattern-mode project (definition):** a copy of the loaded project (after `--seed` is applied) whose
  `arrangement` is exactly one clip `{pattern: i, start_bar: 0.0, repeats: N}` (gain 0, no fades) and whose
  `length_bars = std::ceil(double(N) * pattern_extent(pat) / double(beats_per_bar))`, computed in exactly that
  order in `double`. `opd render --pattern` renders THAT project through the normal path, so the WAV (and, with
  `--stems-dir`, the stems; and with `--format` / `--limit-dbfs`, those options) is **bit-identical** to
  `opd render` of an equivalent hand-written project with that one-clip arrangement. Mute/solo, master gain,
  tempo map, bpm, sample rate stay as in the song; the loop region is not used.
- **Errors** (`error: usage: <detail>` on stderr via the existing `fail("usage", ...)`, exit 2, nothing written),
  checked in this order. 1–4 are option-syntax checks made BEFORE the project file is opened, placed right after
  the existing `--loop`/`--from-bar`/`--to-bar` combination check (so that existing check still wins when
  `--loop` and `--from-bar` are both given):
  1. `--pattern` with `--loop` (either order) → `--pattern cannot be combined with --loop`
  2. `--pattern` with `--from-bar` or `--to-bar` → `--pattern cannot be combined with --from-bar/--to-bar`
  3. `--loops` without `--pattern` → `--loops requires --pattern`
  4. `--loops` value not a decimal integer in `[1, 1000]` (`0`, `-1`, `2.5`, `abc`, empty, `1001`, `1e2`, `+3`, ` 2`)
     → `bad --loops value '<value as given>'`
  5. after the project loads (file errors keep exit 3 / 4 and win): no pattern with that id →
     `unknown pattern '<NAME as given>'` (an empty NAME, a case difference, or a numeric index all count as unknown).
  Then, exit 5 via `fail("render", ...)`: a pattern whose `pattern_extent` is 0 (no notes and no `length_beats`) →
  `pattern '<NAME>' has no length (no notes and no length_beats)`.

## Implementation guide (4 files besides the spec)
1. `src/engine/render.hpp` / `src/engine/render.cpp` — add, in namespace `op`:
   ```cpp
   bool pattern_mode_project(const Project& p, size_t pattern_index, long long loops, Project& out, std::string& err);
   ```
   Requires `pattern_index < p.patterns.size()` and `loops >= 1`. Computes `extent = pattern_extent(pat)`; if
   `!(extent > 0.0)` sets `err` to the no-length message above (with `pat.id`) and returns false. Otherwise
   `out = p`, `out.arrangement` = one `Clip` (`pattern = pattern_index`, `start_bar = 0.0`, `repeats = loops`, other
   fields default), `out.length_bars` per the formula above; returns true. Do NOT change `render_subset` or any
   existing function.
2. `src/cli/main.cpp` — in `cmd_render`: parse `--pattern NAME` and `--loops N` in the option loop (both take a
   value); add the usage line `[--pattern NAME [--loops N]]` to `usage()`; add option-syntax checks 1–4 (use the
   existing `parse_decimal(s, 1000, v)` plus `v >= 1`); after the project loads and the seed override is applied,
   look up the pattern (skip empty ids), fail with message 5 if absent, call `op::pattern_mode_project`, on false
   `return fail("render", err)`, then `p = std::move(solo)` and continue the unchanged path.
3. `tests/test_main.cpp` — new `static void test_pattern_mode()` called from `main`, **≥ 8 new CHECKs**, using
   the existing `parse_text` / `tmp_dir()` helpers (no fixed `/tmp` paths): `pattern_mode_project` yields one clip
   with the right fields and `length_bars` (explicit `length_beats`, derived extent, loops 1 and 3, ceil), the input
   project is untouched, the render equals the render of a hand-written equivalent project (`interleaved` vectors
   equal), and the no-length error string.
